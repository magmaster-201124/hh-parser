# Resumetto

Веб-приложение, которое собирает вакансии с контактами из двух источников — **hh.ru** и **Работа России (trudvsem.ru)** — и показывает их в таблице с фильтром по наличию телефона.

## Возможности

- Сбор вакансий из hh.ru (официальный API с токеном приложения) и trudvsem (открытый API)
- Идемпотентный upsert в PostgreSQL: повторные сборы не создают дубликаты, а обновляют существующие записи
- REST API на FastAPI: список вакансий с фильтром `has_phone`, параметры `limit` и `offset`
- Веб-интерфейс: таблица вакансий, клиентская пагинация по 50 записей, кнопки запуска сбора с отслеживанием статуса в реальном времени
- Healthcheck: эндпоинт `/health` с проверкой доступности БД + Docker healthcheck
- Запуск в Docker Compose или напрямую из командной строки без Docker
- Автоматический фолбэк авторизации hh: если токен из `.env` отклонён (401), приложение получает новый токен приложения через `client_credentials`

## Стек

Python 3.13, FastAPI, SQLAlchemy, PostgreSQL 16, Docker Compose, pytest, ruff.

## Быстрый старт

```bash
git clone https://github.com/magmaster-201124/hh-parser
cd hh-parser
cp .env.example .env   # при наличии; иначе создайте .env по образцу ниже
docker compose up --build -d
```

Пример `.env` (точные имена переменных сверяйте с `app/config.py`):

```python
DATABASE_URL=postgresql+psycopg://parser:parser@db:5432/vacancies
HH_CLIENT_ID=<client id приложения hh>
HH_CLIENT_SECRET=<client secret приложения hh>
HH_API_TOKEN=            # можно оставить пустым — токен будет получен через client_credentials
```

Важно: `.env` содержит секреты и не коммитится (он в `.gitignore`).

После запуска:

- <http://localhost:8000> — веб-интерфейс
- <http://localhost:8000/docs> — интерактивная документация API (OpenAPI)

## Запуск без Docker

Сбор не завязан на FastAPI: провайдеры и запись в БД — обычный код.

```bash
# активировать виртуальное окружение
python -m app.main
```

Перед запуском убедитесь, что PostgreSQL доступен по `localhost:5432` (в Docker Compose порт проброшен наружу, поэтому достаточно запущенного контейнера `db`).

Пример вывода:

```bash
INFO app.providers.trudvsem: Собрано вакансий: 13
INFO app.providers.hh: Собрано вакансий hh: 160
INFO __main__: Итог: собрано 173, новых 0, обновлено 173, с телефоном 12
```

«Новых 0» при повторном прогоне — это работающая идемпотентность: upsert обновил существующие записи вместо создания дубликатов.

## API

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/` | веб-интерфейс |
| GET | `/health` | healthcheck: 200, если БД отвечает; 503 при недоступности |
| GET | `/api/vacancies` | список вакансий; параметры `has_phone`, `limit` (по умолчанию 50, максимум 250), `offset` |
| POST | `/api/collect/hh` | запустить сбор hh.ru (фоновая задача) |
| POST | `/api/collect/trudvsem` | запустить сбор trudvsem (фоновая задача) |
| GET | `/api/status` | состояние последнего сбора по каждому источнику |

Сбор выполняется асинхронно: `POST /api/collect/{source}` сразу отвечает «Сбор запущен», а счётчики (`collected`, `created`, `updated`) появляются в `/api/status` по завершении. Веб-интерфейс опрашивает статус автоматически.

Примеры запросов для VS Code REST Client лежат в `requests.http`.

## Схема данных

Единая таблица `vacancies`: `hh_id` (ключ вакансии), `title`, `company`, `url`, `area`, `salary_from`/`salary_to`/`currency`, `has_phone`, `phone`, `contact_name`, `raw_json` (первичный ответ API), `published_at`, `created_at`, `updated_at`. Первичный ключ — `hh_id`, что и обеспечивает идемпотентность upsert.

## Авторизация hh: как это устроено

- Для поиска вакансий hh требует **токен приложения** (`client_credentials`). Токен соискателя (authorization code flow) для поиска не нужен.
- Запрос нового токена ограничен: не чаще одного раза в 5 минут, иначе API отвечает `refresh too early`. Поэтому токен из `.env` используется напрямую без повторных запросов.
- Каскад: используется `HH_API_TOKEN` из `.env`; если он пуст — токен получается через `client_credentials`. Если токен из `.env` отклонён с кодом 401, выполняется автоматический повтор через `client_credentials`, а в лог пишется подсказка обновить `HH_API_TOKEN`.
- Не запускать диагностические проверки с получением нового app-токена в цикле: каждое получение отзывает предыдущий токен.

## Ограничения источников

- **hh.ru отдаёт контакты редко — и это свойство API, а не ошибка проекта.** Даже в деталях вакансии (`GET /vacancies/{id}`) поле `contacts` возвращается как `null` с пустым списком телефонов в большинстве случаев. Известное поведение зафиксировано в issue [hhru/api#853](https://github.com/hhru/api/issues/853): контакты, видимые на сайте hh, через API не отдаются. Телефон в таблице появляется только там, где работодатель явно указал его в данных, доступных API.
- **trudvsem контакты открыты:** у значительной части записей `has_phone=true`, есть имя контактного лица. Это государственная система открытых данных, где публикация вакансий — обязанность работодателя, а не услуга платформы.
- Веб-пагинация клиентская: страница загружает до 250 записей и листает их по 50 локально; сервер при этом поддерживает серверную пагинацию через `limit`/`offset`.
- В БД нет отдельной колонки источника: обе записи хранятся под общим ключом `hh_id`. Источник можно определить по формату идентификатора (у hh — числовой id, у trudvsem — длинные UUID-подобные ключи). Задокументировано как известное ограничение; улучшение — добавить колонку `source`.
